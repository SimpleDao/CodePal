5. **无多智能体体系**：SearchAgent 是孤岛，无扩展机制
6. **无任务持续性**：刷新即丢失，无法后台执行

5. **状态跳转**：RETRY_WITH_FIX / FIXED_AND_RETRY_REVIEW 等高级跳转

1. **无多智能体体系**：只有工具级抽象，无 Agent 级抽象
2. **LLM 调用与责任链割裂**：LlmInvokeProcessor 不参与链，设计不一致
3. **任务持续性不足**：消息持久化了，但任务执行状态未持久化
4. **缺少计划能力**：PlanTools 存在但未集成到主流程
5. **前端架构文档缺失**：Vue 端架构无说明

```
Agent<TInput, TOutput> (基类，实现 ExecutableTool 接口)
  │
  ├─ MainAgent (主任务 Agent，持有工具列表)
  │    ├─ CodingAgent (编码 Agent)
  │    ├─ DocumentAgent (文档 Agent)
  │    ├─ CodeReviewAgent (审查 Agent)
  │    ├─ ChatDBAgent (数据库 Agent)
  │    └─ ArtifactAgent (原型 Agent)
  │
  └─ SubAgent (子任务 Agent，可被当作 Tool 调用)
       ├─ ErrorRecoveryAgent (错误恢复)
       ├─ AnalysisAgent (内容分析/摘要)
       ├─ CodebaseInvestigatorAgent (代码库调查)
       ├─ DomainDictAgent (领域词典)
       ├─ NanoDSLAgent (UI DSL生成)
       ├─ ChartAgent (图表生成)
       ├─ PlotDSLAgent (统计图表)
       ├─ SqlReviseAgent (SQL优化)
       └─ WebAgent (网页交互)
```

**关键设计：Agent 即 Tool**

> Agent 继承自 ExecutableTool，因此：
> - SubAgent 可以被 MainAgent 当作工具调用
> - Agent 之间可以互相调用（通过 AskAgentTool）
> - 统一的执行接口和生命周期管理
> - 统一的参数验证和错误处理

1. **任务状态不持久化**：刷新后任务丢失（可通过 Server 端补充）
2. **KMP 复杂度**：多平台适配成本高，社区小
3. **渲染系统复杂**：6+ 种 Renderer 实现，维护成本高
4. **缺少工作流编排**：Agent 间协作还是 Tool 调用模式，无 DAG 工作流

## 7. 多智能体协作能力深度对比

### 7.1 四种多智能体范式

```
范式一：工具级子智能体 (LoongC)
  Main ──► Tool (SearchAgent)
  问题：无隔离、无通信、不可扩展

范式二：流水线处理器 (yours_agent)
  Processor1 → Processor2 → ... → ProcessorN
  问题：线性流程、无并行、无Agent抽象

范式三：Agent即Tool (AutoDev)
  MainAgent ─┬─► SubAgent1 (Tool)
             ├─► SubAgent2 (Tool)
             └─► SubAgent3 (Tool)
  优势：统一接口、可组合、可嵌套

范式四：协作式智能体 (Copilot Chat)
  PlannerAgent ←─→ ExecutionAgent ←─→ SearchAgent
         │                │                │
         └────────── Shared Memory ────────┘
  优势：专业分工、并行协作、状态共享
```

### 7.2 演进路径

```
LoongC → yours_agent → AutoDev → Copilot Chat
  │         │          │          │
  ▼         ▼          ▼          ▼

```
