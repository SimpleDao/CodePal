我：动态工具发现 (ToolSearchToolCallAdvisor)：当你给AI配备了上百个工具时，每次请求都把全部工具定义发给模型会消耗海量Token。Spring AI 2.0可以让模型按需搜索并加载最相关的几个工。
这是怎么做到的？

大师：
你的感觉没错，这确实是一个很聪明的设计。Spring AI 2.0 实现这个功能的核心机制，简单来说就是“先藏起来，让模型自己用‘搜索工具’去找”。

它没有一次性把所有工具信息塞给模型，而是分成了两步，在后台完成了一个精妙的“工具发现循环”。
它是如何运作的：一个两步走的发现循环

    第一步：建立索引，但不亮底牌

        建立索引：当系统启动时，ToolSearchToolCallingAdvisor 会先把你注册的所有工具（可能成百上千个）都收集起来，在一个叫 ToolIndex 的地方建立索引，方便后续快速查找。

        隐藏工具：最关键的是，初始请求不会把这些工具的完整定义发给大模型。如果一次性全发过去，Token 消耗会非常巨大。

    第二步：引导模型自主“搜索”

        只给一个“搜索工具”：模型一开始只能看到一个名为 toolSearchTool 的特殊工具。你可以把它的功能理解为“帮我查查，我有什么工具可以完成XX任务”。

        模型主动查询：当模型需要处理任务，发现手头没有直接可用的工具时，它就会调用这个 toolSearchTool，并带上一个搜索关键词，比如“获取天气信息”。

        后台动态注入：Spring AI 收到这个搜索请求后，会用关键词在刚才建立的 ToolIndex 中搜索，找到最匹配的 1-5 个工具（数量可配，默认5个）。

        展开并执行：找到匹配的工具定义后，它们会被动态地“注入”到后续的对话上下文中。这时模型就能看到这些新工具，并正常调用它们来完成任务了。

支持的搜索方式

Spring AI 提供了多种 ToolIndex 实现方式来支撑这种搜索，你可以按需选择：
搜索策略	实现类	适用场景
关键词 (Keyword)	LuceneToolIndex	精确匹配工具名称或描述中的关键词
语义 (Semantic)	VectorToolIndex	处理自然语言查询，理解模糊意图（需配合向量数据库）
正则 (Regex)	RegexToolIndex	通过正则表达式匹配工具名称模式，如 get_*_data
实际效果与权衡

这个设计在节省成本上效果显著。根据 Spring 官方博客的基准测试，在 28 个工具的测试中，这项技术为不同模型节省了 34% 到 64% 的总 Token 消耗。节省的主要来源是大幅降低了 Prompt Tokens（提示词Token）的消耗。

当然，这也带来了一点权衡：因为多了一个“搜索-发现-再调用”的步骤，完成同一个任务，发起给大模型的请求次数会从 3-4 次增加到 4-5 次。

我：可以的。是不是工具长时间不用 还可以淘汰掉？

是的，可以。Spring AI 2.0 不仅支持动态发现工具，也确实提供了淘汰不常用工具的机制。

这一机制主要通过 ToolIndexEvictionStrategy（工具索引淘汰策略） 接口来实现，你可以对工具索引的“生命周期”进行管理，类似于一个缓存。目前主要有以下几种策略，可以帮你按需清理工具：
🧹 淘汰策略的选择
策略	工作机制	适用场景
NeverEvictStrategy	不主动淘汰任何工具，工具索引会永久保留。	仅适合单用户、会话数极少且稳定的开发或测试环境。
AlwaysEvictStrategy	在每次请求前都强制清空并重建索引，保证工具定义绝对最新。	工具集可能在请求间动态变化的场景（例如AI动态生成新工具）。
LruEvictStrategy	基于“最近最少使用”原则，当索引数量超出设定上限时，淘汰最久未使用的工具。	生产环境推荐，可有效控制内存或向量库的占用。
TtlEvictStrategy	为每个工具设置“生存时间”（TTL），超时后自动淘汰。	对工具“新鲜度”要求较高的场景。
CompositeEvictStrategy	组合多种策略，例如同时设置 LruEvictStrategy 和 TtlEvictStrategy，满足复合需求。	需要更精细控制的复杂场景。

    需要注意：官方文档特别指出，如果在生产环境中处理大量短会话时使用NeverEvictStrategy，可能导致内存溢出，因此生产环境一定要考虑使用有限制的淘汰策略。

⚙️ 如何使用

在配置 ToolSearchToolCallingAdvisor 时，就可以通过 evictionStrategy 方法来设置淘汰策略：
java

// 例如，使用 LRU 策略，最多保留 100 个会话的工具索引
ToolIndexEvictionStrategy lruStrategy = new LruEvictionStrategy(100);

ToolSearchToolCallingAdvisor advisor = ToolSearchToolCallingAdvisor.builder()
.toolIndex(myToolIndex)  // 你的工具索引
.maxResults(5)
.evictionStrategy(lruStrategy)  // 设置淘汰策略
.build();

所以，这套机制不仅能动态按需发现工具，还能通过配置不同的淘汰策略，控制工具索引的规模和生命周期，从而有效管理内存和成本。
